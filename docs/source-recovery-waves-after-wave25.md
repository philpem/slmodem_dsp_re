The wave-25 closeout adds one exact timeout function and six native
operation-width recoveries. Its measured starting point is 1852 compared
names: 1161 EXACT, one UNRESOLVED, 35 REGALLOC, 93 BYTES and 562 SIZE;
grade 0-or-1 is 1197. Period differential passes 394 binaries with no failures.
These are proposal baselines, not permanent counts.

The [first bounded pass](recovery-waves-26-29.md) completes the V29 declaration
audit and two negative source families, adds a calibrated relocation-aware data

and audits the six magnitude fixtures. No reconstruction source change is
retained from that pass. The V27 lifecycle follow-up is
[issue #410](https://github.com/philpem/slmodem_dsp_re/issues/410).

## Wave 26: finish the width audit before changing field types

Start with the parked V29 countdown experiment: `TxHdxSCR1V29`,
`TxHdxEQCondV29`, `TxHdxABV29` and `TxHdxQuietV29`, plus every other reader
and writer of the same countdown member. The inherited edits changed the
field and four consumers together; that does not isolate which declaration
the native extensions constrain.

1. Inventory every native load, full-width consumer and narrowing boundary.
2. Apply the both-extension rule before proposing a field retype. Separate
   field width/signedness, local declaration and call-site conversion axes.
3. Declare a bounded crossed experiment only after the inventory identifies
   a discriminator. Preserve all complete-TU functions, data and bindings.

The deliverable can be a justified neutral field with corrected local
carriers. A nearer size alone does not justify an unsigned field. Link the
result to the signedness review in issue #76.

## Wave 27: extend ownership evidence to relocated data

The prior payload screen compared 662 non-relocated initialised-data symbols
and excluded 100 relocation-bearing symbols. Audit the excluded set using
relocation targets and addends, LOCAL/FILE ownership, extents and section
membership. Compare pointer tables by resolved destination, not raw bytes or
name/size alone.

Calibrate the inventory on the recovered `reset_cid` / LOCAL `V23_MRF_FILT`
owner as a positive and a GLOBAL-data reference as a negative. Report matched,
different, unsupported and ambiguous counts over the full selected denominator.
Only original-ELF-backed discrepancies should open new source experiments.
The expected unblockers are TU ownership and declaration boundaries, as in
the CID recovery; this is not a request to repeat its completed seven cells.

## Wave 28: rescreen structural residues after the merged batch

Recompute the old instruction-count and byte-mask queues. The other handover's
139 instruction-band rows and 18-function/29-row mask queue are historical
inputs, not current denominators. Select at most eight high-information
functions in the first batch, with native witnesses for per-arm stores,
pointer/value timing, promoted magnitudes or shared return values.

For each function, record its prediction and falsifier before compiling.
Close a finite source family before reading it as recovery. Stop or reframe
after two non-informative batches. Retain allocation-only negatives and
exhausted source families in the ledger rather than retrying nearby syntax.
Follow issue #22's experiment-design workflow.

before adding tests. Prioritise valid histories that distinguish the native

## Gates and parked work

Every retained source change needs original-instruction evidence, complete-TU
collateral, grade-0-or-1 gain/loss sets, partial-link status and `make phase`.
Record explained structural tradeoffs under the current Playbook; never hide
them behind an aggregate gain. Modern portability remains a separate tier.

`RD_create` stays proof-only UNRESOLVED pending a second independent user of
the same proof contract. Draft PR #303 stays unmerged. Do not reopen the
completed CID seven-cell domain, the earlier 384 reset store-order cells or
allocation-only negatives without a new discriminator.
