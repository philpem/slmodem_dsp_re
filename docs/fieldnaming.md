# Field naming — status and ledger

The reconstruction itself (every function's behavior, differentially
verified against the blob) is COMPLETE as of 2026-09-03 — see
`docs/remaining.md` for that closure. This file tracks the phase that comes
after: naming fields that are already correctly modeled (right size, right
type) but still wear a `type_NNNN`/bare `fNNNN`/`pad_NNNN` placeholder
instead of a real name. See CLAUDE.md's "Naming: fields, and flags" section
for the rulebook this phase runs under — it is not repeated here.

**This is a pure rename/refine pass.** A field rename cannot move generated
code (a `#define` or identifier change is compile-time-only); the only way
this phase can regress the reconstruction is by mis-typing or mis-splitting
a field, which is why every wave gates on the relevant differential tests
staying green, not just on a clean build.

**Numbers are measured, not maintained.** Regenerated by counting unique
`pad_[0-9a-f]+`, `(short|int|long|ptr|flags|byte|word|dword|char|uint
|ushort)_[0-9a-f]+`, and bare `f[0-9a-f]{3,6}` identifiers across `include/`
and `src/`. Where a count here disagrees with a fresh grep, the grep is
right.
