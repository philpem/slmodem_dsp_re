# V.32 register storage model audit

The four-cell period experiment compared a five-element `regs` array plus two adjacent shorts with a seven-element array, under both the original seven-iteration constructor loop and seven explicit zero stores. Its source pin is `dfc23b7d1e92f5913b22b124771211d3e4650771`; the canonical `.build-config` and translation-unit manifest hashes are recorded by [`recovery_v32_register_storage.py`](../tools/recovery_v32_register_storage.py).

Across the 14 translation units that include `v32struct.h` transitively, the seven-element loop model matched the current loop objects 14/14. The explicit five-plus-two candidate matched 13/14 current objects; the seven-element explicit candidate matched that explicit candidate 14/14. The two explicit forms therefore produce identical objects across the measured consumers. The explicit constructor fixtures had already passed: `t_v32fprecr` (6 groups, 583,756 checks) and `t_v32fpdisp` (7 groups, 106,013 checks). Their local, ignored logs are `build/typed-offset-audit293/bounds-candidate/explicit/period/t_v32fprecr.run.log` and `build/typed-offset-audit293/bounds-candidate/explicit/period/t_v32fpdisp.run.log`. The four-cell hashes and per-TU equality decisions are in the ignored build artifact `build/typed-offset-audit293/four-cell-results.tsv`; the complete toolchain commands and version output are in `build/typed-offset-audit293/storage-model-replay.log`.

The original physical extent remains unresolved. Native `LoadReg`/`StoreReg` enforce an index limit of four, which establishes the API range but not the original storage declaration. A seven-element array is compatible with that API, as are five API registers followed by two adjacent state values. The measured explicit-store output does not distinguish those models.

`python3 tools/recovery_v32_register_storage.py` replays all four cells from the immutable Git source pin into `build/v32-register-storage-replay/`. It copies the dependency set into isolated overlays, generates the alternate declaration/consumer expressions and constructor forms, and compiles all 14 transitive consumers per cell with the shared period experiment helper. Its independent A-cell build must match all 14 recorded canonical object hashes before the three candidate comparisons are scored. For every cell it also compiles a `sizeof(regs)` assertion and traces the actual selected `v32struct.h`; the seven-element cells must reject a reference to removed `short_46`/`short_48` members. A deliberate wrong-include control puts the five-plus-two header first and must fail the seven-element size assertion. The script checks the pinned config, dependency manifest, helper and period compatibility header; it appends `DSPLIB_REPRODUCE_BUGS` through `compile_shell`. This makes replay independent of later source changes, including the reviewed constructor edit. `--audit` verifies the retained earlier object table, commands and fixture logs without compiling. The original complete compiler commands, version output, and exact period fixture logs remain under `build/typed-offset-audit293/`.

An earlier promoted-tool run used the overlay root as an include directory, which left the live five-plus-two header ahead of the intended pinned variant; that attempt is preserved as invalid in `build/v32-register-storage-replay/invalid-overlay-root-include-20261018/` and is not evidence. The separate original runners used `-I.../overlay/include` and generated the seven-array explicit stores as `regs[5]` and `regs[6]`; their retained commands and source overlays show the correct selection. The tracked replay now independently verifies both through include tracing, layout assertions, and the wrong-include rejection control.


Production retains the current five-plus-two layout and API and now uses the
seven explicit stores. This restores the observed native initialization graph
without claiming the original array extent. `V32FP_recreate` grows from 3729
to 3745 bytes; the other five function bodies and nontext contents are
unchanged. The production object raw-matches the selected explicit candidate.
The two focused fixtures pass 689769 checks in total, and `make phase J=4`
passes all 392 period fixtures and structural checks.
